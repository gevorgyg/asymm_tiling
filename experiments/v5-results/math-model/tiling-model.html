Asymmetric Tiling Project · Formal Model

A Tile-Shape Cost Model for Asymmetric Matrix Multiply

Revised model incorporating the A reuse factor — with experimental validation from E1b and E2.

Experimentally confirmed · E1b + E2 · max error ≤ 3%

§1 · Setup and Notation

The computation

We compute C = A × B: A has shape M×K, B has shape K×N, C has shape M×N. The computation is tiled: for each C-tile output position (ti, tj), we step through K-slices and accumulate partial products into the C tile. This is called one session.

Hardware uses 3D register tiles: a register tile has shape REG_M × REG_N × REG_K, and the inner loop iterates over register-tile positions within the cache tile.

All symbols

M, N, K Matrix dimensions (elements) TM, TN, TK Cache-tile sizes (elements per axis). TK = K in our setup (one k-slice covers the full K dimension). reg_n Register tile width in the N direction (REG_N = 4 in our hardware) R A reuse factor per session: R = TN / reg_n. How many times each A register tile is loaded within one session. AP, BP, CP Bytes per element (A: 4, B: 4, C: 4 in our setup) Cfill(TM) Cycles to load one A register tile from the memory hierarchy. Depends on TM (which determines whether A fits in L2 or spills to DRAM). Measured: ≈ 13.5 cycles for TM ≤ 48 (L2 regime). α(TM) Effective A cost per unit of MNK: α(TM) = Cfill(TM) / reg_n. Measured: ≈ 3.25 for TM ≤ 48; rises when A spills to DRAM. gc B generation cost: cycles per B element generated by the PRNG FIFO device (= PRNG_FIFO_GEN_COST) L1, L2 Cache sizes in bytes (L1 = 16 384, L2 = 65 536) TML2 Maximum TM before A tile overflows L2: TML2 = L2 / (TK × AP) = 64

§2 · Naive Element Access Counts

Before accounting for the inner-loop structure, we count how many times each unique A and B element is needed across all sessions.

A inter-session accesses
Each of the M×K unique A elements is needed in every N-direction tile session. There are N/TN such sessions per (ti, tk) pair:
Asessions = M·K × (N/TN) = MNK / TN (1)
This counts how many times each A tile is brought in across all sessions — one load per (ti, tj, tk) combination.
B generations
Each of the K×N unique B elements is generated once per M-direction session. There are M/TM such sessions per (tj, tk) pair:
Btotal = K·N × (M/TM) = MNK / TM (2)
B is never cached between sessions — it is regenerated each time from the PRNG FIFO. Total B generation time = (MNK/TM) × gc.

Btotal = MNK/TM is the correct total B cost — B is always regenerated fresh. But Asessions = MNK/TN is not the true A load count. Inside each session, the inner loop causes each A tile to be loaded R times.

§3 · The A Reuse Factor

What happens inside a session

Within one session for output tile (ti, tj), the outer-products inner loop iterates over register-tile positions in the order:

for rtk in 0 .. TK/reg_k: ← K-direction reg tiles
for rtj in 0 .. TN/reg_n: ← N-direction reg tiles [R iterations]
load B[rtk, rtj] ← B loaded once per rtj, held in register
for rti in 0 .. TM/reg_m: ← M-direction reg tiles
load A[rti, rtk] ← A register tile loaded from L1/L2
load C[rti, rtj] ← C tile lives in L1, not registers
C[rti, rtj] += A × B
store C[rti, rtj] ← C written back to L1

B is loaded once per (rtk, rtj) pair and held in a register while all TM/reg_m values of rti are computed. C is not kept in the register file between iterations — it lives in L1 and is loaded and stored on every inner step.

For a fixed (rtk, rti) pair, the A register tile A[rti, rtk] is loaded once per rtj iteration. There are R = TN/reg_n iterations of rtj, so each unique A register tile is loaded R times per session.

True A load count
True A loads = Asessions × R
= (MNK / TN) × (TN / reg_n)
= MNK / reg_n (3)
TN cancels exactly. Total A loads are independent of TN.

Why C_fill(TM) ≈ L2_lat — and why that is a coincidence

The proximity of C_fill to L2_lat is not because each A load costs L2_lat. Experiment E4b (L2_ACCESS_CYCLES sweep) shows that when L2_lat is quadrupled (7→28 cycles), C_fill changes by only 1.6%. Cold L2 fills account for just ~1% of total runtime. The dominant cost is warm L1 hits.

The inner loop does three memory operations per mulacc: load A, load C, store C. With 16 elements per register tile and 64 computations per register-tile group, this is 3×16/64 = 3/4 of a memory op per compute element. Nearly all of these hit L1 (L1 hit rate ≈ 99%) at L1_lat = 4 cycles each. The normalized cost per unit MNK is therefore:

C_fill ≈ (3 mem-ops / mulacc) × (reg_m × reg_k elements / reg-tile) / (reg_m × reg_n × reg_k elements / mulacc) × L1_lat × reg_n
= (3/reg_n) × L1_lat × reg_n = 3 × L1_lat = 3 × 4 = 12 cycles
Measured: 12.95. The gap (8%) is B FIFO overhead and the ~1% cold L2 fill contribution.

C_fill ≈ 12–14 ≈ L2_lat because 3 × L1_lat ≈ L2_lat for our hardware parameters (L1_lat=4, L2_lat=14). That ratio is a property of the cache hierarchy, not of A loading. On a system where L2_lat = 40 cycles, C_fill would still be ≈ 12 but would no longer equal L2_lat.

The ~6% decrease of C_fill with R (from E3-S2) comes from the 1% cold-fill portion: at R=1 every spatial-group cache line is loaded cold; at R=16 the same lines may be L1-warm across tile passes. This is a second-order effect.

Therefore the total A access time is:

T_A = (MNK / reg_n) × Cfill(TM)
= MNK × [ Cfill(TM) / reg_n ]
= MNK × α(TM) (4)
α(TM) = C_fill(TM) / reg_n is a function of TM only — TN has cancelled out completely.
Key departure from the naive model

The naive model wrote T_A = MNK · C_A / TN, treating C_A as a hardware constant. Our finding is that C_A is not constant — it scales as:

C_A = α(TM) × TN

Substituting: T_A = MNK · (α(TM) × TN) / TN = MNK · α(TM). TN is gone. The original ratio rule TM*/TN* = ρt was derived assuming C_A is constant — it does not apply.

§4 · The Full Cost Model

Total time is the maximum of the A access time and the B generation time (in a pipelined system, the slower one dominates):

T = MNK × max( α(TM), gc / TM )

where:

  • MNK × α(TM) is the total A access time — constant in TN, piecewise in TM
  • MNK × gc / TM is the total B generation time — constant in TN, decreasing in TM
  • The max picks the bottleneck: in a pipelined system, A loading and B generation partially overlap
Model assumptions

A1 (C-stationary outer-products): The inner loop order is rtk → rtj → rti as shown in §3. This determines the reuse factor R = TN/reg_n. A different ordering could change R.

A2 (Pipelined max model): T = max(T_A, T_B). A generation and B loading overlap in time; the bottleneck dominates. Experimentally confirmed in E1a: max model error ≤ 2% vs sum model error up to 78%.

A3 (No stalls within a session): The PRNG FIFO has enough capacity that it does not stall during a session. When gc is large and the FIFO stalls, the stall time is already accounted for in the B generation term MNK × gc/TM.

What TN controls

TN does not appear anywhere in T = MNK × max(α(TM), gc/TM). This means TN has no effect on total runtime, within the regime where A fits in L2 and C fits in L1. TN is a free parameter, and the right choice is to maximize TN subject to the C tile fitting in L1:

TN* = L1 / (TM × CP) — constrained to divide N
Larger TN means fewer sessions (better for prefetch locality), but TN has no direct effect on T in the model.

§5 · The α(TM) Function

α(TM) = Cfill(TM) / reg_n is the A-side cost per unit of MNK. Cfill(TM) depends on where the A tile sits in the cache hierarchy:

A tile size = TM × TK × AP bytes
TML2 = L2 / (TK × AP) = 65536 / (256 × 4) = 64 ← L2 boundary

Measured α values (E3 — gc=0, no B-cost contamination)

α rises only ~22% from the L2 minimum (3.237 at TM=32) to the DRAM regime (≈3.94). Once A spills to DRAM the cost per register-tile load saturates: TM=96 and TM=128 have essentially identical C_fill (15.76 vs 15.75), confirming that α is flat past the L2 boundary.

Piecewise approximation

α(TM) ≈
{ 3.25 if TM ≤ 48 (A tile fits in L2) 3.56 if TM = 64 (A exactly fills L2) 3.94 if TM ≥ 96 (A in DRAM, α flat)

For most purposes: in the L2 regime α ≈ 3.25; in the DRAM regime α ≈ 3.94. The moderate and flat rise past the L2 boundary is what makes larger TM sometimes worth pursuing (see §6).

§6 · Tile Shape Optimization

Since T = MNK × max(α(TM), gc/TM) does not depend on TN, the only tuning knob is TM.

The balance condition

Within each cache regime where α is constant, T(TM) = MNK × max(α, gc/TM) is monotonically decreasing in TM (larger TM reduces the B term while α stays fixed). So within a regime we always want TM as large as possible.

The interesting decision is whether to cross into a higher-cost regime (larger α). The crossover condition: A-side cost in the new regime = B-side cost at the new TM:

αnew = gc / TMboundary
⟺ TMboundary = gc / αnew
If TM_boundary > the next regime's minimum TM, it is worth crossing. If TM_boundary is below the current TM, staying is better.
Algorithm — Find optimal TM*
  1. 1.Evaluate T(TM) = MNK × max(α(TM), gc/TM) at each valid TM (powers of 2 that divide M).
  2. 2.The TM with the lowest T(TM) is TM*.
  3. 3.Set TN* = floor(L1 / (TM* × C_P)), rounded down to a divisor of N.

No closed-form formula: the piecewise nature of α(TM) and the discrete constraint that TM must divide M make evaluation the right approach.

Key insight: going past the L2 boundary can be optimal

Because α rises only modestly from L2 to DRAM (3.237 → 3.94, a +22% increase), while gc/TM falls by ×2 each time TM doubles, larger TM in the DRAM regime can beat smaller TM in the L2 regime at high gc. Furthermore, α is flat in the DRAM regime (TM=96 and TM=128 have the same α ≈ 3.94), so larger DRAM-regime TM is almost always better when gc forces us past the L2 boundary.

E4 Result — corrected explanation of C_fill ≈ L2_lat

C_fill ≈ 12–13 cycles is set by warm L1 hits, not L2 cold fills. The formula is C_fill ≈ 3 × L1_lat = 3 × 4 = 12, where "3" is the number of memory operations per mulacc (load A, load C, store C) normalized by register-tile geometry. C_fill ≈ L2_lat = 14 only because 3 × L1_lat ≈ L2_lat for our specific hardware parameters. On any system where that ratio differs, C_fill would track L1_lat, not L2_lat.

The condition for the model to hold: C tile must fit in L1 (TN ≤ L1/(TM×C_P)) and A tile must fit in L2 (TM ≤ L2/(TK×A_P)). These are exactly the constraints already encoded in α(TM) and TN*.
