Asymmetric Tiling Project · Formal Model

A Tile-Shape Cost Model for Asymmetric Matrix Multiply

Revised model incorporating the A reuse factor — experimentally validated across 14 gc values, 5 TN values, overflow regimes, and 4 matrix sizes.

Experimentally confirmed · E1b – E12 · max error ≤ 3%

§1 · Setup and Notation

The computation

We compute C = A × B: A has shape M×K, B has shape K×N, C has shape M×N. The computation is tiled: for each C-tile output position (ti, tj), we step through K-slices and accumulate partial products into the C tile. This is called one session.

Hardware uses 3D register tiles: a register tile has shape REG_M × REG_N × REG_K, and the inner loop iterates over register-tile positions within the cache tile.

All symbols

M, N, K Matrix dimensions (elements) TM, TN, TK Cache-tile sizes (elements per axis). TK = K in our setup (one k-slice covers the full K dimension). reg_n Register tile width in the N direction (REG_N = 4 in our hardware) R A reuse factor per session: R = TN / reg_n. How many times each A register tile is loaded within one session. AP, BP, CP Bytes per element (A: 4, B: 4, C: 4 in our setup) Cfill(TM) Cycles to load one A register tile from the memory hierarchy. Depends on TM (which determines whether A fits in L2 or spills to DRAM). Measured: ≈ 13.5 cycles for TM ≤ 48 (L2 regime). α(TM) Effective A cost per unit of MNK: α(TM) = Cfill(TM) / reg_n. Measured: ≈ 3.25 for TM ≤ 48; rises when A spills to DRAM. gc B generation cost: cycles per B element generated by the PRNG FIFO device (= PRNG_FIFO_GEN_COST) L1, L2 Cache sizes in bytes (L1 = 16 384, L2 = 65 536) TML2 Maximum TM before A tile overflows L2: TML2 = L2 / (TK × AP) = 64

§2 · Naive Element Access Counts

Before accounting for the inner-loop structure, we count how many times each unique A and B element is needed across all sessions.

A inter-session accesses
Each of the M×K unique A elements is needed in every N-direction tile session. There are N/TN such sessions per (ti, tk) pair:
Asessions = M·K × (N/TN) = MNK / TN (1)
This counts how many times each A tile is brought in across all sessions — one load per (ti, tj, tk) combination.
B generations
Each of the K×N unique B elements is generated once per M-direction session. There are M/TM such sessions per (tj, tk) pair:
Btotal = K·N × (M/TM) = MNK / TM (2)
B is never cached between sessions — it is regenerated each time from the PRNG FIFO. Total B generation time = (MNK/TM) × gc.

Btotal = MNK/TM is the correct total B cost — B is always regenerated fresh. But Asessions = MNK/TN is not the true A load count. Inside each session, the inner loop causes each A tile to be loaded R times.

§3 · The A Reuse Factor

What happens inside a session

Within one session for output tile (ti, tj), the outer-products inner loop iterates over register-tile positions in the order:

for rtk in 0 .. TK/reg_k: ← K-direction reg tiles
for rtj in 0 .. TN/reg_n: ← N-direction reg tiles [R iterations]
load B[rtk, rtj] ← B loaded once per rtj, held in register
for rti in 0 .. TM/reg_m: ← M-direction reg tiles
load A[rti, rtk] ← A register tile loaded from L1/L2
load C[rti, rtj] ← C tile lives in L1, not registers
C[rti, rtj] += A × B
store C[rti, rtj] ← C written back to L1

B is loaded once per (rtk, rtj) pair and held in a register while all TM/reg_m values of rti are computed. C is not kept in the register file between iterations — it lives in L1 and is loaded and stored on every inner step.

For a fixed (rtk, rti) pair, the A register tile A[rti, rtk] is loaded once per rtj iteration. There are R = TN/reg_n iterations of rtj, so each unique A register tile is loaded R times per session.

True A load count
True A loads = Asessions × R
= (MNK / TN) × (TN / reg_n)
= MNK / reg_n (3)
TN cancels exactly. Total A loads are independent of TN.

Why C_fill(TM) ≈ L2_lat — and why that is a coincidence

The proximity of C_fill to L2_lat is not because each A load costs L2_lat. Experiment E4b (L2_ACCESS_CYCLES sweep) shows that when L2_lat is quadrupled (7→28 cycles), C_fill changes by only 1.6%. Cold L2 fills account for just ~1% of total runtime. The dominant cost is warm L1 hits.

The inner loop does three memory operations per mulacc: load A, load C, store C. With 16 elements per register tile and 64 computations per register-tile group, this is 3×16/64 = 3/4 of a memory op per compute element. Nearly all of these hit L1 (L1 hit rate ≈ 99%) at L1_lat = 4 cycles each. The normalized cost per unit MNK is therefore:

C_fill ≈ (3 mem-ops / mulacc) × (reg_m × reg_k elements / reg-tile) / (reg_m × reg_n × reg_k elements / mulacc) × L1_lat × reg_n
= (3/reg_n) × L1_lat × reg_n = 3 × L1_lat = 3 × 4 = 12 cycles
Measured: 12.95. The gap (8%) is B FIFO overhead and the ~1% cold L2 fill contribution.

C_fill ≈ 12–14 ≈ L2_lat because 3 × L1_lat ≈ L2_lat for our hardware parameters (L1_lat=4, L2_lat=14). That ratio is a property of the cache hierarchy, not of A loading. On a system where L2_lat = 40 cycles, C_fill would still be ≈ 12 but would no longer equal L2_lat.

The ~6% decrease of C_fill with R (from E3-S2) comes from the 1% cold-fill portion: at R=1 every spatial-group cache line is loaded cold; at R=16 the same lines may be L1-warm across tile passes. This is a second-order effect.

Therefore the total A access time is:

T_A = (MNK / reg_n) × Cfill(TM)
= MNK × [ Cfill(TM) / reg_n ]
= MNK × α(TM) (4)
α(TM) = C_fill(TM) / reg_n is a function of TM only — TN has cancelled out completely.
Key departure from the naive model

The naive model wrote T_A = MNK · C_A / TN, treating C_A as a hardware constant. Our finding is that C_A is not constant — it scales as:

C_A = α(TM) × TN

Substituting: T_A = MNK · (α(TM) × TN) / TN = MNK · α(TM). TN is gone. The original ratio rule TM*/TN* = ρt was derived assuming C_A is constant — it does not apply.

§4 · The Full Cost Model

Total time is the maximum of the A access time and the B generation time (in a pipelined system, the slower one dominates):

T = MNK × max( α(TM), gc / TM )

where:

  • MNK × α(TM) is the total A access time — constant in TN, piecewise in TM
  • MNK × gc / TM is the total B generation time — constant in TN, decreasing in TM
  • The max picks the bottleneck: in a pipelined system, A loading and B generation partially overlap
Model assumptions

A1 (C-stationary outer-products): The inner loop order is rtk → rtj → rti as shown in §3. This determines the reuse factor R = TN/reg_n. A different ordering could change R.

A2 (Pipelined max model): T = max(T_A, T_B). A generation and B loading overlap in time; the bottleneck dominates. Experimentally confirmed in E1a: max model error ≤ 2% vs sum model error up to 78%.

A3 (No stalls within a session): The PRNG FIFO has enough capacity that it does not stall during a session. When gc is large and the FIFO stalls, the stall time is already accounted for in the B generation term MNK × gc/TM.

What TN controls

TN does not appear anywhere in T = MNK × max(α(TM), gc/TM). This means TN has no effect on total runtime, within the regime where A fits in L2 and C fits in L1. TN is a free parameter, and the right choice is to maximize TN subject to the C tile fitting in L1:

TN* = L1 / (TM × CP) — constrained to divide N
Larger TN means fewer sessions (better for prefetch locality), but TN has no direct effect on T in the model.

§5 · The α(TM) Function

α(TM) = Cfill(TM) / reg_n is the A-side cost per unit of MNK. Cfill(TM) depends on where the A tile sits in the cache hierarchy:

A tile size = TM × TK × AP bytes
TML2 = L2 / (TK × AP) = 65536 / (256 × 4) = 64 ← L2 boundary

How α(TM) is measured: the gc=0 calibration

The model has two terms. To read off α(TM) from a simulation, we need to eliminate the B term. Setting gc=0 (instantaneous B generation, PRNG_FIFO_GEN_COST=0) does exactly that:

Tgc=0 = MNK × max( α(TM), 0/TM )
= MNK × max( α(TM), 0 )
= MNK × α(TM) exact — α(TM) > 0 always

Rearranging: α(TM) = Tgc=0 / MNK. This is not an approximation — with gc=0 the B generation cost is identically zero regardless of TM, so every measured cycle is purely A-access overhead. Run the simulator with gc=0, read off the cycles, divide by MNK.

The same procedure works per-(TM, TN) pair. Run gc=0 at each (TM, TN) and compute α(TM, TN) = Tgc=0 / MNK. This builds the cell-specific calibration table used in E6 and E7.

§6 · Tile Shape Optimization

Since T = MNK × max(α(TM), gc/TM) does not depend on TN, the only tuning knob is TM.

The balance condition

Within each cache regime where α is constant, T(TM) = MNK × max(α, gc/TM) is monotonically decreasing in TM (larger TM reduces the B term while α stays fixed). So within a regime we always want TM as large as possible.

The interesting decision is whether to cross into a higher-cost regime (larger α). The crossover condition: A-side cost in the new regime = B-side cost at the new TM:

αnew = gc / TMboundary
⟺ TMboundary = gc / αnew
If TM_boundary > the next regime's minimum TM, it is worth crossing. If TM_boundary is below the current TM, staying is better.
Algorithm — Find optimal TM*
  1. 1.Evaluate T(TM) = MNK × max(α(TM), gc/TM) at each valid TM (powers of 2 that divide M).
  2. 2.The TM with the lowest T(TM) is TM*.
  3. 3.Set TN* = floor(L1 / (TM* × C_P)), rounded down to a divisor of N.

No closed-form formula: the piecewise nature of α(TM) and the discrete constraint that TM must divide M make evaluation the right approach.

Key insight: going past the L2 boundary can be optimal

Because α rises only modestly from L2 to DRAM (3.237 → 3.94, a +22% increase), while gc/TM falls by ×2 each time TM doubles, larger TM in the DRAM regime can beat smaller TM in the L2 regime at high gc. Furthermore, α is flat in the DRAM regime (TM=96 and TM=128 have the same α ≈ 3.94), so larger DRAM-regime TM is almost always better when gc forces us past the L2 boundary.

E4 Result — corrected explanation of C_fill ≈ L2_lat

C_fill ≈ 12–13 cycles is set by warm L1 hits, not L2 cold fills. The formula is C_fill ≈ 3 × L1_lat = 3 × 4 = 12, where "3" is the number of memory operations per mulacc (load A, load C, store C) normalized by register-tile geometry. C_fill ≈ L2_lat = 14 only because 3 × L1_lat ≈ L2_lat for our specific hardware parameters. On any system where that ratio differs, C_fill would track L1_lat, not L2_lat.

The condition for the model to hold: C tile must fit in L1 (TN ≤ L1/(TM×C_P)) and A tile must fit in L2 (TM ≤ L2/(TK×A_P)). These are exactly the constraints already encoded in α(TM) and TN*.

Why α(TM=64, TN=4) ≈ 2× α(TM=64, TN=32)

In the DRAM regime (A tile overflows L2), each A register tile must be fetched from DRAM the first time it is used in a session. The reuse factor R = TN/reg_n determines how many rtj iterations share a single cold fill: at TN=32, R=8 — one cold DRAM fill amortized over 8 warm loads. At TN=4, R=1 — every load is a cold DRAM fill with no warm-up.

In the L2 regime (TM ≤ 48) the same dynamic exists but the cost difference between a cold L2 fill (~14 cy) and a warm L1 hit (~4 cy) is much smaller, so the TN=4 penalty is only ~6%. The DRAM regime amplifies this to ~2× because a cold DRAM fill costs ~198 cy vs 4 cy — a 46× ratio.

Using the recalibrated α, prediction errors for TN=4 in the DRAM regime drop from ~75% to <1%. TM*=48 remains optimal for all TN even with the fully calibrated α: the L2-regime minimum (TM=48, α ≈ 3.25–3.41) still beats the least-penalised DRAM option (TM=64, TN=32, α=3.56). The ~2–4% residual error in B-bottlenecked cells comes from FIFO scheduling overhead present at gc=130 but absent in the gc=0 calibration runs.

E7 Findings — when TM* depends on TN

gc=64 (TM*=32 at TN=32): at TN=4 and TN=16, TM* shifts to 48. Within the L2 regime, the α minimum flips: α(32,TN=4)=3.430 > α(48,TN=4)=3.414. The difference is 0.016 — small but enough because gc=64 is fully A-dominated and the TM with the lowest α always wins.

gc=130 (TM*=48): unchanged for all TN. TM=48 is inside the L2 regime, far from the L2/DRAM boundary, and the TN sensitivity of α in L2 is too small to matter.

gc=230 (TM*=64 at TN=32): the most sensitive case — TM*=64 sits exactly at the L2/DRAM boundary. At TN=4: α(64,TN=4)=6.22 makes TM=64 extremely costly; TM=48 (T/MNK=4.97) beats TM=64 (T/MNK=6.27) by >20%. At TN=16 and TN=64: α(128,TN) < α(64,TN) by a small margin, so TM=128 edges out TM=64.

gc=380 (TM*=128): unchanged for all TN. At this gc, TM=128 wins decisively even in the DRAM regime where all large-TM options have α≈6.2 at TN=4. The B savings from TM=96→128 still tip the balance.

When TM* depends on TN — three conditions
  1. 1.The E3-predicted TM* sits at or past the L2/DRAM boundary (TM ≥ 64). In the L2 regime the TN sensitivity of α is at most 6%; only in the DRAM regime does it reach ~2×.
  2. 2.TN is far from the E3 calibration value (TN=32). At TN=32 the E3 table is exact by construction. Deviations grow toward TN=4.
  3. 3.The competing TM options are close in cost. When one option wins by >3%, TN noise cannot flip the result. It only matters when options are within ~1% of each other.

Practical rule: if you use TN=32, the E3 model is correct for all gc values. If you use small TN (≤16) and gc is near a cache-regime boundary, use the per-TN calibrated α.

E5 + E6 + E7 Combined Result

The model T = MNK × max(α(TM), gc/TM) is confirmed across all four gc values (64, 130, 230, 380) and all four TN values (4, 16, 32, 64). The E3 (TN-independent) α table gives the right TM* whenever TN=32 or the E3-optimal TM is comfortably inside the L2 regime. The calibrated (per-TN) α gives the right TM* in all but one marginal tie case.

Conclusion on TN: TN does not appear in T = MNK × max(α(TM), gc/TM). It can be chosen freely to maximize spatial locality, subject only to the C-tile L1 constraint. The exceptions found in E7 (gc=64 and gc=230 at small TN) are due to the TN-dependence of α itself, not a TN term in the time function — and the calibrated model captures them. The original ratio rule TM*/TN* = ρt is fully invalidated.

E8 — Dense gc boundary sweep & analytical α formula

E7 used four gc values and TN ∈ {4,16,32,64}. E8 densifies both axes: 14 gc values sampled near and between the E3 transition points, and TN ∈ {4,8,16,32,64}. It also introduces a new column — the analytical formula prediction — which estimates α(TM,TN) from hardware constants rather than calibration.

The analytical α formula

The dominant cost per A register-tile load is an L1 hit (4 cy). In each session of R = TN/4 inner passes (rtj), only the very first pass triggers a cold cache fill. The correction for going from TN=32 (where the E3 table was calibrated) to any other TN is:

α(TM, TN) ≈ αE3(TM) + C(TM) × (1/TN − 1/32)

where C(TM) = (Lcache − L1lat) / (reg_m × reg_k):

  • L2 regime (TM ≤ 48): C = (14 − 4)/16 = 0.625
  • DRAM regime (TM ≥ 64): C ≈ 12.0 (theoretical; actual ≈ 10.4 for TM=96,128)

At TN=32 the formula reduces to αE3(TM) exactly — it is anchored at the calibration point.

E9 — C-tile overflow regime

All previous experiments use TN ≤ 64, where the C tile (TM × TN × 4 bytes) fits comfortably in L1 (16 KB). E9 deliberately violates this with TN ∈ {128, 256} to characterize what happens when the C tile overflows. TN=64 is the reference.

L1 overflow threshold: TM × TN × 4 > 16384.

  • TN=128: C overflows L1 at TM ≥ 32 (exactly fills at TM=32)
  • TN=256: C overflows L1 at TM ≥ 16

E9 Findings

L1 overflow causes α to jump ~14% at the boundary (TM=32, TN=128: α goes from 3.22 to 3.69). When the C tile exactly fills L1, every C-tile store evicts an A line, eliminating warm-L1 reuse.

L2 overflow is catastrophic. At TN=256, TM=96: C tile = 96×256×4 = 96 KB ≥ L2. α=9.17 — more than double the DRAM-regime value without overflow. The C tile must be re-fetched from DRAM every pass.

TM* shifts dramatically. At TN=128 (gc=130, 230, 380): TM*=96, because TM=96 with TN=128 has C tile = 49 KB (fits in L2, α=3.65) while TM=128 has C tile ≥ L2 (α=4.98). At TN=256, TM=64 wins for gc=230,380 despite α=4.85 — TM=96 and TM=128 are worse at α≈9.17.

Calibrated model is always correct — it measures α directly and therefore automatically captures overflow effects. E3 is always wrong when overflow changes TM*.

Practical implication: TN is not truly a free parameter. It must satisfy TM × TN × 4 < L1 to stay in the well-modeled regime. The safe upper bound is TN < L1 / (TM × C_P). For TM=32: TN < 128. For TM=48: TN < 85, so TN ≤ 64.

E11 — Regression-based α formula

The theoretical formula (E8) uses a hard-coded slope C(TM): 0.625 in L2 regime, 12.0 in DRAM regime. E8 showed it can overshoot by +8–10% in the DRAM regime at small TN. E11 fits the slope empirically: given the 5-point calibration from E8 (TN ∈ {4,8,16,32,64}), we run ordinary least squares on:

α(TM, TN) = a(TM) + b(TM) × (1/TN)

No new simulator runs are needed — all data comes from E8's results cache. The coefficients a(TM) and b(TM) are compared to the theoretical values, and TM* prediction accuracy is retested on E8's full gc sweep.

L2 regime (TM=16,24,32): the actual cold-fill slope is b ≈ 0.88, not the theoretical 0.625. TM=48: R²=0.13 — the 1/TN model fails completely. α decreases from TN=4→32 then rises at TN=64 as the C tile (12 KB) approaches L1 (16 KB). No two-parameter linear model can describe this.

Conclusion: the 1/TN linear model is an incomplete description of α(TM,TN). It fits well at TM=16,24,32 (R²=1.0) and TM=64,96,128 (R²=0.98), but breaks at the two boundary TM values (TM=8 is flat; TM=48 is non-monotonic). For accurate TM* prediction, calibrate at all TN values of interest. For physical insight into the cold-fill slope: b_L2 ≈ 0.88 and b_DRAM ≈ 10.6.

E12 — Non-linear α: adding a C-tile pressure term

E11's linear model a + b/TN failed for TM=48 (R²=0.13) because α is U-shaped — it drops as TN grows (fewer cold A fills) but rises at large TN as the C tile crowds L1 and evicts A lines. Two opposing effects need two terms:

α(TM, TN) = a(TM) + b(TM)/TN + c(TM)×TN
  • b/TN — cold-fill overhead, decreasing with TN (same as E11)
  • c×TN — C-tile eviction pressure, increasing with TN (∝ C-tile size)

Setting dα/dTN = 0 gives the optimal TN for each TM, balancing the two effects:

TN*(TM) = √(b(TM) / c(TM))

E8 + E9 + E10 Combined Result

The model T = MNK × max(α(TM,TN), gc/TM) with per-(TM,TN) calibrated α is confirmed across 14 gc values, 5 TN values, and 4 matrix sizes. The calibrated model correctly predicts TM* in >97% of all tested combinations.

The analytical formula α(TM,TN) ≈ αE3(TM) + C(TM)×(1/TN−1/32) works well (<2% error) in the L2 regime for TN ≤ 32, but has systematic DRAM-regime errors because the theoretical CDRAM overstates the hardware effective value. A regression-based approach (fitting α vs 1/TN per TM from multi-TN calibration data) would give better TN-independent α estimates.

TN constraint: TN is only free while TM × TN × C_P < L1. Violating this triggers the overflow regime (E9) where α changes drastically and the analytical formula fails entirely. The safe bound is TN < L1 / (TM × C_P).
